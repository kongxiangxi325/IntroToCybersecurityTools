## 一、作业背景

### 1.1 为什么用 CTFHub

CTF（Capture The Flag）是一种以解题拿 flag 为目标的网络安全练习方式。CTFHub 的技能树把知识点拆成一个个小关卡，每道题都有独立靶场和即时反馈，适合刚接触信息安全的大一同学建立“动手感”。

本次不追求刷完整个 Web 技能树，只做最基础的 6 道题。它们分别对应 HTTP 报文的不同位置：请求方法、URL 路径、请求头、状态码和响应体。做完之后，你应该能把 6 道题串成一张 HTTP 请求/响应结构图，而不是记住 6 个孤立的技巧。

**flag 是门票，WP 才是成绩。** 只抄到一个 flag、说不出原理，不能算完成本次作业。

允许用 AI 查概念、解释报错和梳理解题思路；但请求和操作必须你自己在 Kali 中复现，截图必须是你自己的题目画面。直接让 AI 给 flag、代写 WP，或者把网上的 writeup 截图当成自己的，都不算完成。

## 三、最小知识：一张 HTTP 报文图

### 3.1 请求和响应的基本结构

一次 HTTP 请求大致长这样：

```http
GET /index.php HTTP/1.1
Host: example.ctfhub.com:10080
User-Agent: Mozilla/5.0
Cookie: name=value

```

一次 HTTP 响应大致长这样：

```http
HTTP/1.1 302 Found
Location: /index.html
Set-Cookie: session=...
Content-Type: text/html

<html>...</html>
```

你需要能指出：

- **请求行**：方法、路径、HTTP 版本；
- **请求头**：Host、Cookie、Authorization 等；
- **状态行**：200、302、401、403、404 等；
- **响应头**：Location、Set-Cookie、Content-Type 等；
- **响应体**：HTML、目录列表、错误信息、flag 等。

### 3.2 几个容易混淆的概念

| 概念 | 要点 |
| --- | --- |
| GET 与 POST | 都是 HTTP 方法；方法不止这两种，服务器也可以接受自定义方法 |
| 200 与 302 | 200 表示成功返回内容；302 表示临时重定向，浏览器通常会自动跟随到 `Location` |
| Cookie 与 Session | Cookie 存在客户端，Session 通常存在服务端；不要把权限判断只放在 Cookie 里 |
| Base64 | 一种编码方式，不是加密；看到 Base64 不要当成“加密后的密码” |
| 目录列表 | Web 服务器把目录下的文件列出来，可能泄露备份、源码、配置等敏感文件 |

### 3.3 curl 速查

| 需求 | 命令 |
| --- | --- |
| 查看状态码和响应头 | `curl -i URL` |
| 自定义请求方法 | `curl -X 方法名 URL` |
| 添加 Cookie | `curl -b "name=value" URL` |
| 添加请求头 | `curl -H "Header: value" URL` |
| Basic 认证 | `curl -u 用户名:密码 URL` |
| 跟随 302 跳转 | `curl -L URL` |
| 只看响应头 | `curl -I URL` |
